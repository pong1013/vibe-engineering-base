# Offer Template and Skill Entrypoints

`vibe-engineering-base` will support two equal entrypoints: a GitHub template for starting a new project and a user-scoped `$vibe-engineering` Skill for adding the Harness and repository-learning capabilities to an existing writable folder, whether or not it is a Git repository. The template onboarding will lead with one Codex setup prompt and run `make verify` after project identity, instructions, contract, and checks are configured. Leading with bootstrap verification was rejected because it does not help a new user turn the base into their project, while requiring every existing project to adopt the template was rejected because it excludes established and non-Git workspaces.

`$vibe-engineering` will expose setup, upgrade, status, and learn intents. Installation and upgrade will use a versioned manifest and checksums: unmodified managed files may update automatically, modified files require a preview and explicit merge decision, `AGENTS.md` changes stay inside a bounded managed block, project-created Skills remain project-owned, and any conflict or failed validation leaves no partial update. A pure chat without a writable project folder may receive recommendations but cannot claim durable installation or learning.

The Skill may propose a new project Skill only after the same reusable pattern appears at least twice or the user explicitly identifies it as a standard workflow. The first creation requires a preview. Repository-scoped `harness-feedback` remains the mechanism for routing concrete evidence into durable project guidance, checks, or Skills, while repository-scoped `grill-with-docs` is removed according to ADR 0015. `$vibe-engineering` is a project setup and maintenance capability. This decision supersedes ADR 0016's requirement to expose and install the separate Global Workflow from this repository; ADR 0001's separation boundary remains in force.
