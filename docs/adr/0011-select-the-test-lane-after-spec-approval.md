# Select the Test Lane After Spec Approval

Immediately after the user approves the specification, the Workflow Controller will determine whether the work has independently testable behavior. When it does, ticketing is followed automatically by parallel Implementation and Test Agents with separated write ownership; when it does not, the controller skips the Test Agent, records the reason, and still runs the Project Contract's verification. Starting a Test Agent for every change was rejected because documentation and other non-behavioral work have no meaningful independent test surface, while leaving the choice until after implementation was rejected because tests should be derived from the approved requirements rather than the resulting code.

If meaningful tests are warranted but the repository lacks the necessary test infrastructure, the controller raises an Exception Gate instead of treating the absence as permission to proceed without tests. After specification approval, `to-tickets`, implementation and testing, verification, and review run without routine phase confirmations; only a newly discovered consequential decision, risk, scope change, or stalled loop interrupts the sequence.
